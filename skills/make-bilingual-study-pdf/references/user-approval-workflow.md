# 用户先确认格式，再看样张，再全量制作

本规范约束执行 Skill 的代理与接手的施工队，适用于作业、论文和讲义，不是只针对某一份文档的验收备注。
固定顺序是：**格式确认 → 小范围真实样张 → 用户明确批准 → 全量制作与自动审计 → 成品人工验收**。
自动测试证明工程约束，没有资格替用户决定阅读格式；样张批准也不代表整份文档已通过验收。

这是代理编排层的必停规则，不是新 CLI 参数、Profile schema 或机器 gate。现有 `pipeline.py status`
与 `qa-report.json` 不会自动读取下述协作记录；代理必须在已有技术门禁之外执行本规范，不能声称
脚本已经强制实现了样张批准。既有源完整性、冻结绑定、文件安全与最终视觉审查要求全部保留。

## 1. 格式确认：先复述已知需求，只问真正缺失的选择

读取当前请求与可靠的既有确认，给用户一份简短的格式说明。已经明确的要求直接写入，不反复提问；
未确认项给出一个建议默认值，集中询问影响结果的少数选择，不让用户填写技术配置表。
格式说明至少覆盖：

- 阅读组织：普通正文按完整逻辑段落英文在前、中文在后；Problem 等结构块的范围、语言排列与跨页方式。
- 视觉与保留：字号和留白、标题层级、边框/底色、页眉页脚；代码、公式、图表、图注与链接如何呈现。
- 交付与用途：阅读设备或打印用途，需要的 Markdown、DOCX、PDF/可选 TeX，以及拟展示的样张范围。

`format-spec.md` 和所选 Profile 是已实现格式的基线，不等于用户已批准，也不是任意定制排版的承诺。
用户要求与支持范围不一致时，先解释限制并提出可支持的选择或单独的实现任务；不得静默改需求、
手改冻结 Profile，或把尚未实现的左右对照/其他语言等能力当作现有开关。
语言方向、原文不可变、内容不遗漏及代码/公式/链接保护等核心约束不能被格式偏好覆盖。

格式尚不明确时，只进行必要的文件/依赖预检与代表片段选择；不要开始全量翻译、反复全量排版，
或安装未经批准的依赖。格式说明确认后，先进入样张制作，而不是直接全量执行。

## 2. 样张：用实际内容与实际生产链验证最难的格式

优先使用本次源文档中的真实片段和真实译文，已有合格译文可复用但须重新校验源绑定。
通常从约 2–4 个输出页开始；这个数不是截断完整题目的上限。选择少量有代表性的完整逻辑块，
不只展示封面、两行标题或最容易成功的纯文字页。按文档实际包含的元素覆盖：普通中英段落、
完整结构块、代码/公式/图表，以及一个跨页或复杂边界情况；没有的元素注明不适用。

作业样张必须展示一整道有正文的 Problem：题干、子题、题内小标题、代码/公式及最后一项交付要求，
并展示其后明确的题外内容。原文存在长题时，还须覆盖跨页续文。验收要同时看“末项没有掉到框外”
和“题外内容没有被吞进去”，不能以标题数量正确或边线存在代替。若完整成员缺乏源证据，明确
暂停在结构复核/修复；不得靠邻近猜测补范围，也不得将标题框样张称为完整题目容器。

样张必须经过与全量相同的提取、分组、翻译记录、构建和所选编译后端。不得用手画的 PDF、独立
美化模板或修改生成物的方式做出生产链无法复现的效果。样张使用全量拟采用的字体、版式与工具链。
不得用“中文译文：”加英文的测试占位响应代替真实译文；公开合成 fixture 可以继续用于工程回归，
但不能代替当前用户的格式样张，也不能改写冻结 expected 来美化验收结果。

### 隔离与完整性

为样张创建独立的 `PROOF_WORK`，与全量 WORK 互不嵌套，均位于 active Skills roots 和课程代码仓库之外。
对原生 PDF，可在不改原件的前提下制作完整选定逻辑块的独立摘页副本；记录原 PDF SHA-256、
原始页码与摘页顺序，并保留判断边界所需的相邻内容。样张 WORK 的源审计只证明这个摘页副本，
不能被搬到全量 WORK 充当整本证明。不要截掉题目末尾、覆盖原件，或在完整 WORK 中删除未译块来通过审计。

现有脚本若要求完整响应，就完整翻译样张 WORK 内的内容，再走正常构建；不得以未完成的全量翻译
伪造完整 build。MinerU 样张仍须有与样张源 PDF 精确匹配的已冻结导入证据；不能重写原始 hash、
剪裁解析器 JSON 后冒充匹配，也不能为打样擅自运行重型后端。不能安全构造代表样张时说明阻碍并暂停。

先自行检查样张每页、修掉已知缺陷，再向用户展示 **样张 PDF 与可直接查看的页面渲染**，说明实际
覆盖了哪些结构、还有哪些未覆盖。不要只报告测试通过、交付本地路径，或让用户从海量 CI 文件里找图。
当前渠道无法查看文件时，保持待确认，不假定用户已经看过。

## 3. 样张批准：展示后必须停下，不能边等边做全量

展示时明确询问是否按这一版用于全量制作，然后等待用户答复。批准必须在上下文中明确指向
这版可查看的样张和全量制作，不要求用户背诵固定口令。收到文件、泛泛夸奖、沉默、CI 绿灯、
施工队自评或过去另一份文档的批准，都不等于本次授权。

提出修改时，先只改样张、重新展示并再次等待。不能把“改完某处再给我看”理解为可以修改后立即
全量运行。用户主动提出复用旧模板时，复用已确认偏好以减少询问，但仍展示本次真实代表内容。

只用一份本地 `review-notes.md` 保持交接，不新增审批服务、数据库、通用状态机或第二套审计报告。
它放在样张和全量 WORK 的外部协作目录，不放在会被重建清理的 `output/` 或 `translation/`，
也不进入安装负载。最小记录为：

```text
格式说明版本与已确认要求：
源文件 SHA-256、Profile/版式标识、生产代码或负载版本：
样张版本、原始页码/逻辑块范围、PDF SHA-256、对应渲染：
采用的后端、字体与工具链：
用户对这一版的明确答复及其对话出处：
当前停点、下一步允许做什么：
成品版本及最终人工验收结果（尚未发生则写待验收）：
```

只按实际发生的确认填写。批准原话和私有样张留在本地/原对话；公开仓库仅记录必要的脱敏结论，
不上传私有文档、截图、路径或私人对话。换代理或恢复会话时先读记录，核对样张和当前配置；
证据缺失或版本不一致时停下来补确认，不根据记忆猜测已获批准。

## 4. 批量制作：沿已批准方案执行，不在背后换格式

只有样张获明确批准，且已发现的结构/技术阻碍已解决，才能开始全量翻译、构建与完整文档验收。
无需每批翻译都找用户确认；沿现有可恢复批次和审计流程执行，已有精确版本的有效证据不重复跑。
可复用样张译文和已验证数据，但要匹配全量请求的 ID、源字节、术语表与保护项，并重新审计；
不能直接复制样张的合并响应或 passed 报告。

影响可见结果的变化，例如题目分组、语言排列、字体、页宽、模板、后端或重新断句，必须更新格式
记录并重做受影响的样张，取得新批准后再继续全量。全量中首次遇到样张未覆盖的结构，也应先做
小范围增补样张；不要悄悄套用猜测规则。纯日志或其他有证据表明不影响可见输出的修改无需重走
全部格式问询，但仍执行受影响的技术验证。不得复用已过时的 PDF 或视觉批准。

## 5. 成品验收：样张通过不是整本通过

全量自动审计通过后，仍须按 `qa-rules.md` 检查全部 contact sheets 和规定的全分辨率页面，向用户
提供最终 PDF、页面预览和风险页索引，请其完成最终确认。代理预检可以帮助发现问题，不能冒充人类
批准；用户只看了部分页面时如实记录覆盖范围，不能填写 `reviewed-pages all`。

样张批准仅授权生产，不能复制为完整 WORK 的 `visual-review.json`，也不能令全文 QA 自动通过。
格式改变、重建 DOCX 或重新编译 PDF 后，既有最终视觉证据按原规则失效。可先交付明确标为
“待人工验收”的候选成品，但只有完整技术链通过、所需真实人工视觉记录有效且用户确认最终成品，
才能称“已完成/已验收”。确认格式也不授权合并仓库、发布版本、安装依赖或替换已安装 Skill。

## 维护者复核要点

交接时逐项检查实际行为：需求不明时停问；只有格式确认时只做样张；仅有自动绿灯时不批量；
用户要求改样时重新展示；换会话无确认记录时暂停；批准后正常批量；版式漂移时重新打样；
样张通过而最终视觉未完成时不宣称整本通过。现有自动测试和安全检查照常执行，不能用本规范
暂停无关的代码单测，也不能把单测运行解释为用户批准。
